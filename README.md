# Kotoba Room

Интерактивный веб-воркбук по японскому языку для совместного занятия ученика и учителя. Первый урок посвящён て-форме глаголов и создан на основе материалов из `te грамматика.pdf`, а механика упражнений — после анализа `Первая Неделя.html`.

## Что уже работает

- регистрация с выбором роли «Ученик» или «Учитель»;
- вход по уникальному логину без пароля;
- создание комнаты учителем;
- персональная ссылка-приглашение;
- вход одного ученика именно в приглашённую комнату;
- синхронизация ответа ученика с экраном учителя через Socket.IO;
- сохранение ответов и комнат на сервере;
- статусы и комментарии учителя, которые сразу появляются у ученика;
- индикатор присутствия;
- ученик видит результат только после отметки учителя;
- адаптивный интерфейс для компьютера и телефона;
- четыре раздела: образование て-формы, `〜てください`, последовательность `V₁-て V₂`, три значения `〜ています`.

## Установка на Ubuntu/Debian VPC

Сначала клонируйте репозиторий, затем запустите установщик из его каталога:

```bash
git clone https://github.com/Coffee313/jp_workbook.git
cd jp_workbook
sudo bash install.sh --server-name ВАШ_IP --open-firewall
```

Скрипт автоматически:

- устанавливает Node.js 22, Nginx и OpenSSL;
- устанавливает зависимости и запускает тесты;
- создаёт systemd-сервис `jp-workbook`;
- хранит рабочие данные отдельно в `/var/lib/jp-workbook`;
- создаёт самоподписанный HTTPS-сертификат;
- настраивает Nginx, HTTPS и WebSocket proxy;
- проверяет Node.js и HTTPS endpoints;
- откатывает unit и конфигурацию Nginx, если проверка не прошла.

После установки откройте `https://ВАШ_IP`. Самоподписанный сертификат обеспечивает шифрование, но браузер покажет предупреждение о недоверенном центре сертификации. Для публичного домена впоследствии лучше заменить его сертификатом Let's Encrypt.

Порт приложения остаётся доступен только через loopback; извне открываются 80/443. Если на VPC используется облачный security group, разрешите входящий TCP 80 и 443 отдельно — `--open-firewall` управляет только активным UFW внутри ОС.

Если `--server-name` не указан, установщик использует первый IPv4-адрес сервера. На VPC с публичным NAT лучше явно передать публичный IP или домен. Wildcard `server_name _` не используется, чтобы не конфликтовать со стандартным сайтом Nginx. Повторный запуск после неудачной попытки сохраняет данные комнат в `/var/lib/jp-workbook`.

Просмотр состояния и журналов:

```bash
sudo systemctl status jp-workbook
sudo journalctl -u jp-workbook -f
```

## Ручной локальный запуск

Требуется Node.js 22 или новее.

```bash
npm install
npm start
```

Откройте `http://localhost:3000`.

Внутренние параметры можно задать переменными окружения:

```bash
HOST=127.0.0.1 PORT=8080 DATA_DIR=/var/lib/jp-workbook npm start
```

Данные создаются в `data/store.json`. Каталог `data/` исключён из Git, чтобы пользовательские логины и ответы не попадали в репозиторий.

## Тесты

```bash
npm test
```

Проверяются API авторизации, разграничение ролей, приглашения, сохранение данных, двусторонняя realtime-синхронизация, логика учительской проверки и статические контракты интерфейса.

Полный браузерный сценарий (Chrome должен быть установлен):

```bash
CHROME_PATH=/path/to/google-chrome npm run qa
```

Он автоматически создаёт учителя и ученика во временном хранилище, проходит приглашение, проверяет передачу ответа и комментария, измеряет мобильное переполнение и создаёт снимки в `artifacts/`.

## Важное ограничение авторизации

Текущая авторизация намеренно не использует пароль, как и требовалось для первого этапа. Поэтому она подходит для прототипа и доверенной учебной среды, но не защищает аккаунт от входа человеком, который знает логин. Перед публичным production-развёртыванием следует добавить пароль или одноразовую ссылку, ограничение частоты запросов, HTTPS и срок жизни сессий.

## Production

Приложению нужен постоянный Node.js-процесс и WebSocket-поддержка. GitHub Pages не подходит, потому что realtime-комнаты требуют backend. Для одного процесса достаточно текущего JSON-хранилища; перед горизонтальным масштабированием следует перейти на PostgreSQL/Redis и общий Socket.IO adapter.
